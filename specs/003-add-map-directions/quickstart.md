# Quickstart — 예식장 지도와 길찾기 검증

기능 구현 후 저장소 루트에서 실행한다. Python 3.11과 `uv`, 확정 예식장 자료, 대표 지도 이미지, 확인한 지도 링크를 준비한다. iPhone Safari와 Android Chrome에서 각각 지도 앱이 설치된 상태와 없는 상태를 확인할 수 있어야 한다.

## 1. 미리보기 생성

[데이터 모델](data-model.md)에 맞춰 `invitation.json`에 지도 정보를 입력한다. T맵 공식 호출을 적용했다면 공개 웹에 사용할 수 있는 프로젝트 키를 생성 환경에 설정한다. 예식장 홈페이지 핀을 그대로 복사하면 실제 도로명 주소와 어긋날 수 있으므로 먼저 도로명 주소와 대조한다.

```sh
uv run --no-cache --python 3.11 python scripts/generate_invitation.py
uv run --no-cache --python 3.11 python -m http.server 8000 --bind 127.0.0.1
```

`http://localhost:8000/`에서 예식 정보, 지도, 네이버 지도·카카오맵·T맵 버튼을 확인한다. 실제 휴대폰에서 접속하려면 신뢰하는 로컬 네트워크에서 서버에 PC의 LAN 주소를 바인딩하고 휴대폰으로 그 주소를 연다.

## 2. 화면과 길찾기 확인

| 검증 | 방법과 기대 결과 |
| --- | --- |
| 목적지 일치 | 대표 지도 마커와 세 서비스의 도착 위치를 확정 주소에 대조한다. 도착점이 다른 건물이나 반대편 접근로로 지정되는지 확인한다. 각 서비스를 지원 환경에서 확인해 4곳을 모두 기록한다. |
| 앱 설치 | iOS Safari와 Android Chrome에서 앱마다 버튼을 한 번 눌러 목적지가 지정되는지 확인한다. 특히 iOS 카카오맵에서 목적지 유실, Android T맵에서 도착지 누락 여부를 확인한다. 청첩장 복귀 후 예약한 웹 이동이 발생하지 않아야 한다. |
| 앱 미설치 | iOS Safari와 Android Chrome에서 동일 서비스 웹 화면의 예식장 주소를 확인한다. 같은 서비스 웹 화면이 없으면 주소와 다른 지도 안내가 나와야 한다. |
| 데스크톱·인앱·JavaScript 미사용 | 데스크톱에서 키보드와 마우스로, 카카오톡 인앱 브라우저와 JavaScript를 끈 브라우저에서 사용 가능한 경로를 각각 확인한다. 앱 전환이 제한된 환경은 웹 또는 주소를 이용할 수 있어야 한다. |
| 반응형·지도 오류 | 뷰포트 320·390·1280 CSS 픽셀에서 가로 스크롤, 포커스 표시, 최소 44 × 44 CSS 픽셀의 터치 영역을 확인한다. 개발자 도구에서 지도 이미지 요청만 차단하고 동일한 폭에서 예식장 이름과 주소를 읽고 세 버튼을 선택할 수 있는지 확인한다. |
| 하객 확인 | 참여자 5명에게 길찾기 영역에서 예식장 마커와 평소 쓰는 지도 버튼을 찾아보도록 한다. 4명 이상이 10초 안에 모두 찾는지 기록한다. |

별도 작업 복사본에서 잘못된 좌표, 잘못된 서비스 호스트, 존재하지 않는 지도 경로를 각각 넣어 생성기가 필드명과 함께 오류를 표시하고 기존 출력물이 유지되는지 확인한다. 지도 설정을 생략한 기존 초안은 기존 단일 링크로 미리볼 수 있어야 한다.

## 3. 배포 경로 확인

최신 예식 정보와 지도를 모두 대조한 후 확정본 설정으로 게시 번들을 준비한다. 아래 명령에서 서버는 직전 미리보기 서버를 종료한 후 실행한다.

```sh
wedding_preview_dir="$(mktemp -d)"
uv run --no-cache --python 3.11 python scripts/generate_invitation.py --publish-dir "$wedding_preview_dir/wedding"
uv run --no-cache --python 3.11 python -m http.server 8000 --bind 127.0.0.1 --directory "$wedding_preview_dir"
```

`http://localhost:8000/wedding/`에서 지도 이미지와 나머지 리소스가 정상 로드되고 세 버튼이 의도한 목적지로 연결되는지 확인한다. 게시 워크플로가 성공하면 모바일과 데스크톱에서 실제 Pages 주소를 열어 이 검사를 반복한다. 예식장이 바뀌면 좌표와 이미지, 링크를 갱신한 뒤 목적지 비교부터 다시 한다.
