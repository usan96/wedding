# UI and Link Contract — 예식장 지도와 길찾기

## 청첩장 화면

- 예식장 이름과 주소가 있는 영역에서 마커가 찍힌 대표 지도 한 장을 바로 볼 수 있다. 이미지에는 예식장 이름을 포함한 대체 텍스트를 넣고 출처를 인접하게 표시한다.
- 지도 아래에 **네이버 지도**, **카카오맵**, **T맵** 순으로 레이블이 있는 항목 세 개를 제공한다. 이동할 경로는 링크로, 청첩장 안에서 안내만 여는 동작은 버튼으로 제공한다. 모바일에서 각 조작 영역은 최소 44 × 44 CSS 픽셀이고, 키보드 포커스 표시를 제공한다. 작은 화면에서는 버튼이 줄바꿈될 수 있다.
- 대표 지도에만 의존하지 않고 주소를 선택할 수 있는 텍스트로 표시한다. 지도 이미지 오류나 로딩 지연이 주소와 버튼을 가리거나 비활성화하지 않는다.

## 서비스 연결

| 버튼 | 앱을 열 수 있는 환경 | 앱을 열 수 없거나 데스크톱인 환경 |
| --- | --- | --- |
| 네이버 지도 | `nmap://route/car`에 `dlat`(위도), `dlng`(경도), `dname`(이름), `appname`(현재 청첩장 URL)을 전달한다. Android Chrome은 `com.nhn.android.nmap`과 인코딩한 HTTPS 대체 링크를 지정하는 인텐트를 쓴다. | 확인한 네이버 지도 장소 상세 HTTPS 링크를 연다. |
| 카카오맵 | 공식 `/link/to/`의 모바일 연결로 목적지를 전달한다. 실기기에서 해당 연결이 목적지를 보존하지 않으면 검증된 환경에 앱 `route` 호출을 적용한다. | 카카오맵 `https://map.kakao.com/link/to/{이름},{위도},{경도}`에서 해당 목적지를 확인한다. 카카오의 연결 화면이 나타나는 경우 앱 설치 없이 웹에서 보는 선택지가 동작해야 한다. |
| T맵 | 앱에서 발급한 장소 공유 링크가 목적지를 전달하면 이를 사용한다. 필요한 경우 [연구 결과](../research.md#t맵)의 공식 호출을 적용한다. 공식 호출에는 `goalname`, `goalx`(경도), `goaly`(위도)를 전달한다. | 해당 예식장 정보가 표시되는 검증된 T맵 장소 공유 링크가 있으면 연다. 없으면 예식장 주소와 다른 지도 서비스를 이용할 수 있다는 안내를 청첩장 안에서 제공한다. |

### 동작 규칙

1. 앱 실행은 사용자의 직접 입력으로 시작한다. 일반 링크 열기 동작과 브라우저가 제공하는 앱 열기 확인을 존중한다. 현재 위치 접근 및 경로 확정은 지도 서비스가 처리한다.
2. iOS의 스킴 실행 후 웹 이동이 예약된 경우 페이지가 숨겨지거나 떠날 때 취소한다. 앱에서 청첩장으로 돌아왔을 때 웹 링크가 뒤늦게 열리지 않아야 한다. 다음 버튼 선택은 앞선 선택의 예약 동작을 취소한다.
3. 앱 전환 지원을 확인할 수 없는 인앱 브라우저나 JavaScript가 꺼진 환경에서는 HTTPS 링크 또는 청첩장 안의 대체 안내를 이용할 수 있어야 한다. 앱과 웹을 모두 사용할 수 없는 경우의 예시 문구는 “T맵을 열 수 없으면 위 주소를 복사하거나 다른 지도를 선택해 주세요.”이다.
4. 외부 서비스의 서버 장애나 앱 열기 거부 시 사용자는 청첩장으로 돌아와 다른 버튼과 주소를 사용할 수 있다. 원래 화면에서 웹 대체 링크를 이용할 수 있게 하고 동일 앱 열기를 자동으로 반복하지 않는다.
