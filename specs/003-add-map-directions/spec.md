# Feature Specification — 예식장 지도와 길찾기

**Feature Branch** `main`

**Created** 2026-11-20

**Status** Draft

**Input** 사용자 요청 “길찾기에는 네이버 지도, 카카오맵, T 맵, 이 3가지를 바로 연동해서 볼 수 있는 버튼과 대표로 지도가 보이게 해줘”

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 원하는 지도 서비스로 예식장 길찾기 (Priority: P1)

하객은 평소 쓰는 지도 서비스에서 예식장까지의 경로를 확인하고 싶다. 청첩장의 길찾기 버튼을 한 번 누르면 선택한 서비스에 예식장이 목적지로 전달된다.

**우선순위 이유** 하객이 예식장 주소를 다시 검색하거나 입력하지 않고 익숙한 서비스로 찾아갈 수 있다.

**독립 검증** 모바일에서 네이버 지도, 카카오맵, T맵을 각각 눌러 서비스에 표시된 목적지가 청첩장의 예식장 이름과 주소에 해당하는지 확인한다.

**수용 시나리오**

1. **주어진 상황** 선택한 서비스의 앱이 설치되어 있고 앱 열기가 지원된다. **행동** 하객이 해당 버튼을 한 번 누른다. **기대 결과** 선택한 앱이 열리고 예식장이 목적지로 지정된다.
2. **주어진 상황** 앱을 열 수 없고 선택한 서비스가 웹에서 목적지 표시를 지원한다. **행동** 하객이 해당 버튼을 누른다. **기대 결과** 같은 서비스의 웹 화면에서 예식장 위치 또는 해당 목적지의 경로를 확인할 수 있다.
3. **주어진 상황** 선택한 서비스를 앱과 웹에서 모두 열 수 없다. **행동** 하객이 해당 버튼을 누른다. **기대 결과** 이용 가능한 대체 수단을 안내하고, 하객은 청첩장에서 주소를 읽어 복사하거나 다른 지도 서비스 버튼을 선택할 수 있다.

---

### User Story 2 - 청첩장 안에서 예식장 위치 확인 (Priority: P1)

하객은 청첩장 안에서 예식장이 어디에 있는지 먼저 확인하고 싶다. 길찾기 영역에서 예식장 이름, 주소와 함께 예식장이 표시된 대표 지도 한 개를 볼 수 있다.

**우선순위 이유** 하객이 다른 화면을 열기 전에 예식장의 위치와 주변을 파악할 수 있다.

**독립 검증** 모바일과 데스크톱에서 길찾기 영역을 열고 지도에서 표시한 위치와 화면의 예식장 이름 및 주소를 대조한다.

**수용 시나리오**

1. **주어진 상황** 대표 지도를 표시할 수 있다. **행동** 하객이 길찾기 영역을 본다. **기대 결과** 별도의 조작 없이 예식장 위치가 표시된 지도 한 개와 예식장 이름 및 주소를 확인할 수 있다.
2. **주어진 상황** 대표 지도를 표시할 수 없다. **행동** 하객이 길찾기 영역을 본다. **기대 결과** 예식장 이름과 주소를 읽을 수 있고 세 서비스 버튼을 사용할 수 있다.
3. **주어진 상황** 하객이 작은 모바일 화면 또는 데스크톱에서 청첩장을 연다. **행동** 하객이 길찾기 영역을 보고 버튼을 조작한다. **기대 결과** 가로 스크롤 없이 지도, 주소, 버튼이 화면에 맞고, 모바일에서는 가로와 세로가 각각 최소 44픽셀인 영역을 터치해 각 버튼을 실행할 수 있다. 데스크톱에서는 마우스와 키보드로 버튼을 선택하고 실행할 수 있으며 키보드로 선택한 버튼을 화면에서 구분할 수 있다.

### Edge Cases

- 이름이 같거나 비슷한 예식장이 검색되는 경우, 지도와 각 버튼을 확정된 예식장 주소와 대조한다.
- 지도 표시가 지연되거나 실패해도 예식장 이름, 주소, 버튼은 이용할 수 있다.
- 예식장 정보가 바뀌면 대표 지도에 표시되는 위치와 세 버튼의 목적지를 최신 확정 주소와 다시 대조한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 길찾기 영역은 예식장 위치가 표시된 대표 지도 한 개와 예식장 이름 및 주소를 표시해야 한다. 지도는 하객이 별도로 조작하지 않아도 표시되어야 한다.
- **FR-002** — 같은 영역에 ‘네이버 지도’, ‘카카오맵’, ‘T맵’ 버튼을 각각 한 개씩 표시해야 한다. 앱을 열 수 있는 모바일 환경에서는 각 버튼을 한 번 선택하면 해당 앱을 열고 예식장을 목적지로 전달해야 한다.
- **FR-003** — 앱을 열 수 없는 환경에서는 선택한 서비스에 해당 예식장을 표시하는 웹 화면이 있으면 그곳으로 연결해야 한다. 앱과 웹을 모두 이용할 수 없는 경우에는 청첩장의 주소와 나머지 서비스 버튼을 이용할 수 있도록 안내해야 한다.
- **FR-004** — 청첩장에 표시되는 예식장 이름과 주소, 대표 지도, 세 서비스의 목적지는 모두 사용자가 확정한 동일한 예식장을 가리켜야 한다. 게시 전과 예식장 정보 변경 시 모두 대조해야 한다.
- **FR-005** — 길찾기 영역은 모바일과 데스크톱에서 가로 스크롤 없이 읽을 수 있어야 한다. 모바일에서 각 버튼의 터치 영역은 가로와 세로가 각각 최소 44픽셀이어야 한다. 데스크톱에서는 마우스와 키보드로 모든 버튼을 사용할 수 있어야 하며, 키보드로 선택한 버튼이 시각적으로 구분되어야 한다.
- **FR-006** — 대표 지도가 표시되지 않아도 예식장 이름과 주소를 읽을 수 있고 세 서비스 버튼을 선택할 수 있어야 한다.

### Key Entities *(include if feature involves data)*

- **예식장** — 사용자가 확정한 이름과 주소로 식별하는 예식 장소. 대표 지도와 세 서비스가 공통으로 가리키는 목적지다.
- **대표 지도** — 청첩장의 길찾기 영역에 표시하는 예식장 주변 지도. 확정된 예식장의 위치를 표시한다.
- **지도 서비스 버튼** — 네이버 지도, 카카오맵, T맵에 각각 대응하며, 하객이 선택한 서비스에서 동일한 예식장을 확인하는 수단이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — 대표 지도 한 개와 세 서비스의 연결 결과, 총 4곳에서 가리키는 위치가 확정된 예식장 주소와 일치한다. 각 서비스는 연결을 지원하는 환경에서 확인한다.
- **SC-002** — 지원되는 모바일 환경에서 각 서비스 버튼을 한 번 눌러 예식장이 지정된 화면에 도달한다. 앱을 열 수 없는 환경에서는 각 버튼이 해당 서비스의 웹 화면 또는 주소와 다른 서비스 버튼을 이용할 수 있다는 안내를 제공한다.
- **SC-003** — 정상적으로 지도가 표시된 상태에서 검증 참여자 5명 중 4명 이상이 길찾기 영역을 본 뒤 10초 안에 지도에서 예식장 위치와 원하는 지도 서비스 버튼을 찾는다.
- **SC-004** — 화면 너비 320픽셀, 390픽셀, 1280픽셀에서 길찾기 영역을 가로 스크롤 없이 이용할 수 있다. 대표 지도 표시를 차단한 상태에서도 세 화면 모두에서 예식장 이름과 주소를 읽고 세 버튼을 선택할 수 있다.

## Assumptions

- 대표 지도는 예식장 위치와 주변을 확인할 수 있는 지도 한 개로 정의한다. 지도 제공사는 지정하지 않았으며, 확대나 이동 기능은 필수 요건으로 두지 않는다.
- 청첩장 안에서는 예식장 위치를 보여준다. 출발지 선택, 교통수단 설정과 경로 계산은 하객이 고른 지도 서비스에서 지원하는 범위에 따른다.
- 지도와 연결에 쓰는 목적지 정보는 사용자가 확정한 예식장 이름과 주소를 기준으로 한다. 예식장 변경 시 세 서비스의 도착 위치와 대표 지도에 표시된 위치를 확인할 수 있어야 한다.
- 앱 실행과 웹에서의 목적지 표시는 각 서비스와 기기에서 지원하는 범위에 따른다.
