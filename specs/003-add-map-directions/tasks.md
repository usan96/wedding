# Tasks — 예식장 지도와 길찾기

**입력** [명세](spec.md), [구현 계획](plan.md), [조사 결과](research.md), [데이터 모델](data-model.md), [화면·연결 계약](contracts/directions.md), [검증 절차](quickstart.md)

**작업 표기** `[P]`는 선행 작업을 마친 뒤 같은 파일을 수정하는 작업 없이 병행할 수 있는 항목이다. `[US1]`, `[US2]`는 각 사용자 스토리다. 구현 경로는 저장소 루트 기준이다.

## Phase 1 — 준비

- [X] T001 별도 작업 복사본에서 `invitation.json`을 현재 초안 그대로 `scripts/generate_invitation.py`로 생성하고, `index.html`의 예식 정보와 기존 단일 길찾기 링크를 이후 비교 기준으로 확인한다.
- [X] T002 `invitation.json`의 예식장 이름·도로명 주소를 확정 자료와 대조하고 도착 위치 후보를 확인한다. 예식장 홈페이지의 핀과 도로명 주소 위치가 다른 점을 [조사 결과](research.md#예식장-위치-대조)에 따라 확인하고, 일치한 건물 위치와 도착점의 근거를 `specs/003-add-map-directions/research.md`에 기록한다. 위치 후보와 공개 배포에 사용할 확정값을 구분한다.

## Phase 2 — 공통 기반

- [X] T003 `scripts/generate_invitation.py`에서 [데이터 모델](data-model.md#예식장)의 `예식장.venue_name`, `예식장.venue_address`, `예식장.directions`, `예식장.directions_url`에 따라 기존 예식장 검증을 재사용하고 지도 설정 분기를 추가한다. 중복 필드와 정의되지 않은 하위 필드를 검사하고, 지도 설정이 없는 기존 입력은 단일 링크로 미리보며 게시에서는 지도 설정을 요구한다. 필드 오류 시 기존 생성물을 보존한다.
- [X] T004 `scripts/generate_invitation.py`에서 [데이터 모델](data-model.md#지도-설정)의 `지도 설정.latitude`, `지도 설정.longitude`를 공통 목적지 좌표로 읽고 검증한다. 서비스 링크와 지도 렌더링은 이 설정과 기존 예식장 정보를 사용한다.

**확인 지점** 기존 입력의 미리보기와 지도 설정의 공통 검증을 유지하면서 두 스토리 작업을 시작할 수 있다.

## Phase 3 — US1 원하는 지도 서비스로 예식장 길찾기 (P1)

**목표** 네이버 지도·카카오맵·T맵에서 동일한 예식장을 열고 앱 전환이 어려울 때 웹 화면이나 주소를 안내한다.

**독립 검증** 임시 지도 이미지를 사용하는 로컬 초안에서도 모바일 버튼을 각각 한 번 눌러 목적지 전달을 확인한다. 앱 미설치 또는 앱 전환이 제한된 환경에서는 같은 서비스의 웹 화면이나 주소 안내에 도달하는지 확인한다.

- [ ] T005 [P] [US1] `specs/003-add-map-directions/research.md`에 네이버 지도 장소 상세 주소, 카카오맵의 iOS 목적지 전달, T맵 장소 공유 링크의 iOS·Android 앱 및 웹 동작을 확인해 기록한다. T맵 공유 링크가 앱에 목적지를 넘기지 않으면 승인된 공개 웹 키를 사용하는 공식 호출을 검증하고, 확인할 수 없는 환경은 남은 검증으로 기록한다.
- [X] T006 [P] [US1] [화면·연결 계약](contracts/directions.md#서비스-연결)의 직접 실행 규칙에 맞춰 `invitation.js`에서 네이버 지도 스킴과 Android 인텐트 처리, 명시적 웹 대체 경로, 연속 클릭 및 앱 전환 시 예약 동작 취소를 구현한다. 카카오맵과 T맵은 렌더링된 HTTPS 링크를 기본으로 쓰고 확인된 직접 실행 방식만 적용할 수 있게 한다. 기존 공유 기능을 유지한다.
- [X] T007 [P] [US1] `styles.css`에서 세 버튼의 반응형 배치, 최소 44 × 44 CSS 픽셀 조작 영역, 키보드 포커스 표시를 정의한다.
- [X] T008 [US1] `scripts/generate_invitation.py`에 [데이터 모델](data-model.md#지도-설정)의 `지도 설정.naver_place_url`, `지도 설정.tmap_place_url`, `지도 설정.TMAP_PUBLIC_APP_KEY` 검증과 서비스 링크 생성을 추가한다. 네이버 지도 장소 상세 링크와 카카오맵 목적지 HTTPS 링크를 제공하고, T005에서 확인한 T맵 연결 방식과 웹 대체 경로를 구성한다. 공식 호출을 사용하는 경우 기존 Pages 생성 단계 `.github/workflows/pages.yml`에 공개 웹 사용이 확인된 키를 환경 설정으로 전달한다.
- [X] T009 [US1] `templates/invitation.html`과 `scripts/generate_invitation.py`에서 지도 서비스 버튼 세 개, 웹 대체 링크와 주소 안내를 생성하고 `invitation.js`에 연결한다. JavaScript 없이도 링크나 안내를 이용할 수 있게 하고, T005의 결과에 따라 필요한 모바일 직접 실행 분기를 적용한다.
- [ ] T010 [US1] `specs/003-add-map-directions/quickstart.md`의 앱 설치·미설치·복귀 시나리오를 `index.html` 미리보기에서 실행하고, iOS Safari와 Android Chrome의 세 앱 목적지, 데스크톱·인앱·JavaScript 미사용 시 대체 동작을 기록한다. 목적지가 확인되지 않은 직접 실행 경로는 완료로 처리하지 않는다.

**확인 지점** 완성된 대표 지도 없이도 세 버튼과 앱·웹 대체 흐름을 검증할 수 있다.

## Phase 4 — US2 청첩장 안에서 예식장 위치 확인 (P1)

**목표** 길찾기 영역을 열면 예식장 마커, 이름과 주소가 보인다. 지도 이미지가 실패해도 주소와 길찾기 버튼을 이용할 수 있다.

**독립 검증** 검증용 서비스 링크를 구성한 로컬 미리보기에서 앱을 실행하지 않고 지도 핀과 주소를 대조한다. 지정한 화면 폭에서 지도 요청을 차단해도 주소와 버튼을 이용할 수 있는지 확인한다.

- [X] T011 [P] [US2] [대표 지도 조사](research.md#대표-지도)와 T002의 주소 대조 결과를 바탕으로, 예식장 마커와 주변 도로가 보이는 정적 지도 `assets/venue-map.png`를 제작한다.
- [X] T012 [P] [US2] `styles.css`에서 대표 지도와 출처 표기가 작은 화면에서도 읽히고 가로 스크롤을 만들지 않도록 배치한다. 이미지 표시 여부와 관계없이 주소와 버튼을 조작할 수 있게 한다.
- [X] T013 [US2] `scripts/generate_invitation.py`에서 [데이터 모델](data-model.md#지도-설정)의 `지도 설정.map_image`를 검증하고, 미리보기 상대 경로와 게시 번들 이미지 복사를 적용한다. `templates/invitation.html`에 예식장 이름을 포함한 대체 텍스트 및 OpenStreetMap 출처와 함께 지도 한 장을 렌더링한다.
- [X] T014 [US2] `specs/003-add-map-directions/quickstart.md`의 화면과 지도 오류 시나리오를 `index.html` 미리보기의 320·390·1280 CSS 픽셀에서 확인한다. 정상 표시에서는 마커와 주소를 대조하고, 이미지 요청을 차단한 상태에서는 주소와 세 버튼을 사용할 수 있는지 확인한다.

## Implementation Strategy

초기 시연은 US1의 세 버튼과 앱·웹 대체 흐름을 우선 확인한다. 요청한 기능의 완성 범위는 두 P1 스토리이며, 대표 지도와 세 서비스 연결을 함께 검증한 뒤 게시용으로 준비한다.

## 구현 검증 기록

- Chromium에서 320·390·1280픽셀의 가로 스크롤, 터치 영역과 키보드 포커스를 확인했다. 지도 요청 차단과 JavaScript 미사용 상태에서도 주소와 대체 경로를 이용할 수 있었다.
- 잘못된 지도 설정 15건에서 오류 메시지와 생성물 보존을 확인했다. 기존 단일 링크 미리보기와 게시 전 필수 설정 검사도 통과했다.
- 로컬 `/wedding/`에서 검증용 T맵 설정으로 만든 번들을 열어 지도 이미지와 T맵 호출에 전달하는 목적지 값을 확인했다.
- 사용자가 제공한 T맵 링크를 입력하고 링크의 예식장 이름과 주소를 대조했다. 키 없이 만든 로컬 `/wedding/` 번들과 미리보기에서 브라우저의 JavaScript 사용 여부와 관계없이 버튼이 같은 공유 링크로 열리는 것을 확인했다.
- T005·T010의 설치 앱 전환과 목적지 전달은 실기기 확인이 필요하다. T018의 참여자 검증과 T019의 실제 배포 확인도 남았다.

### 수렴 작업 검증

- T021은 320·390·1280 CSS 픽셀의 미리보기와 로컬 `/wedding/` 게시용 파일에서 확인했다. 외부 지도 요청이 실패한 뒤 돌아오면 도움말, 주소와 버튼을 모두 사용할 수 있다. 브라우저 JavaScript 사용 여부와 관계없이 확인했다.
