# Phase 0 Research: 예식 일정 위 사진 갤러리

## 사진 선택과 표시 순서

- **결정** — `invitation.json`에 순서 있는 선택 목록 `gallery_photos`를 둔다. 항목마다 `path`와 선택 설명 `alt`를 받는다. 작성자가 공개하기로 한 사진을 기존 사진 입력 경로인 `assets/`에 준비한다.
- **근거** — 표지와 갤러리를 한 번에 미리 볼 수 있다. 저장소의 `images/`에 있는 원본의 포함 여부와 순서는 작성자가 정할 수 있다.
- **검토한 대안** — 디렉터리 일괄 수집은 파일명으로 순서가 정해지고, 승인하지 않은 사진이 포함될 수 있다. 별도 목록 파일은 입력과 검증 흐름을 하나 더 만든다.

## 생성 검증과 게시

- **결정** — 기존 사진 검증을 재사용하고 항목별 오류 위치를 전달한다. 기존 예시 사진 `sample.png`와 내용이 같은 파일을 확정 입력에서 거부한다. 미리보기에서는 원본을 상대 경로로 참조하고, 게시본에서는 목록 순번으로 이름을 정한 파일을 임시 번들에 복사한 뒤 번들을 공개 경로에 옮긴다.
- **근거** — 생성기가 이미 경로 범위, 파일 확장자, 파일 내용, 예시 여부를 검증한다. 게시 시 개별 파일을 복사하면 작성자가 선택한 사진만 배포되고 원본의 파일명이 같아도 충돌하지 않는다. 기존 미리보기의 임시 파일 교체와 게시 번들의 임시 디렉터리 조립을 재사용할 수 있다.
- **검토한 대안** — `assets/` 전체 복사는 선택하지 않은 자료도 게시한다. 목적지에 바로 쓰면 복사 실패 시 조립 중인 번들이 남는다.

## 레이아웃과 이미지 로딩

- **결정** — 제목을 붙인 HTML 섹션에 사진을 입력 순서대로 세로로 배치한다. 사진의 비율을 유지하고, 설명을 이미지 대체 텍스트에 연결하며, 브라우저 기본 지연 로딩을 사용한다. 작성자는 용량이 큰 원본을 표시 크기에 맞춰 준비할 수 있다.
- **근거** — 청첩장 본문 최대 폭은 25rem이다. 한 열에서 사진 크기를 확보하면서 화면 읽기 순서와 표시 순서를 맞추기 쉽다. 개별 이미지의 로드 실패는 일정이나 다른 사진 동작을 가로막지 않는다. 기존 원본 사진은 장당 약 6~19MB로, 지연 로딩과 별개로 개별 전송 크기도 고려해야 한다.
- **검토한 대안** — 다열 배열은 좁은 화면에서 각 사진이 작아진다. 자동 넘김과 확대 기능은 상호작용을 추가한다. 생성 중 재인코딩은 이미지 처리 의존성과 게시 처리 시간을 추가한다.
