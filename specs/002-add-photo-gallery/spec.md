# Feature Specification: 예식 일정 위 사진 갤러리

**Feature Branch** — `main`

**Created** — 2026-11-20

**Status** — Draft

**Input** — 일정 전에 사진들을 보여줄 수 있는 영역이 필요해

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 예식 일정 위에서 사진 보기 (Priority: P1)

하객은 청첩장을 읽다가 인사말과 예식 일정 사이에서 웨딩 사진을 보고, 같은 페이지에서 예식 일시와 장소를 확인한다.

**우선순위 근거** — 사진 감상과 예식 정보 확인이 하객의 주된 이용 흐름이다.

**독립 검증** — 공개용 사진 3장이 등록된 청첩장을 휴대폰과 데스크톱에서 열어 사진 위치와 순서, 예식 정보와 길찾기 이용 여부를 확인한다.

1. **Given** 작성자가 공개할 사진을 `assets/`에 넣었을 때 **When** 하객이 인사말 아래로 스크롤하면 **Then** 예식 일정 바로 위에 파일명 사전순으로 배치한 대표 사진이 보이고, 사진을 선택하면 상세 보기에서 전체 사진을 넘겨 볼 수 있다.
2. **Given** 하객이 모바일 또는 데스크톱으로 청첩장을 열었을 때 **When** 갤러리에서 예식 일정으로 이동하면 **Then** 가로 스크롤 없이 사진과 예식 일시·장소를 확인하고 길찾기 링크를 이용할 수 있다.
3. **Given** 설명이 등록된 갤러리 사진이 있을 때 **When** 하객이 화면 읽기 프로그램으로 갤러리를 읽으면 **Then** 해당 사진의 설명을 들을 수 있다.

---

### User Story 2 - 공개할 갤러리 사진 관리하기 (Priority: P2)

청첩장 작성자는 `assets/`에 사진을 넣거나 파일명을 바꾼 뒤 갤러리 결과를 미리 본다.

**우선순위 근거** — 사진이 확정된 후 작성자가 공개 범위와 표시 순서를 직접 관리할 수 있어야 한다.

**독립 검증** — 사진을 추가하고 파일명을 바꿔 다시 생성한 뒤, 폴더 밖 사진과 예시 사진의 게시 여부, 빈 폴더, 유효하지 않은 사진을 각각 확인한다.

1. **Given** 작성자가 여러 사진을 `assets/`에 넣었을 때 **When** 청첩장을 생성하면 **Then** 모든 사진이 파일명 사전순으로 반영되고 표지 사진은 기존 설정을 따른다.
2. **Given** `assets/`에 지원 이미지 파일이 없을 때 **When** 청첩장을 생성하면 **Then** 갤러리 제목과 영역이 생략되고 예식 일정이 표시된다.
3. **Given** 지원 확장자를 가진 유효하지 않은 사진이 `assets/`에 있을 때 **When** 청첩장을 생성하면 **Then** 작성자는 문제 경로와 원인을 확인할 수 있고 이전에 성공한 결과는 보존된다.
4. **Given** 작성자가 공개할 사진을 `assets/`에 넣었을 때 **When** 게시용 결과를 생성하면 **Then** 그 폴더에서 발견한 사진이 갤러리에 포함된다. 해당 폴더에 예시 사진이 있으면 게시용 검증에서 거부된다.

### Edge Cases

- 사진이 1장만 등록되어도 같은 위치에 갤러리가 표시된다.
- 하객이 청첩장을 열었을 때 사진 한 장을 불러오지 못해도 나머지 사진과 예식 일정, 길찾기는 이용할 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 갤러리 사진이 1장 이상 등록되면 청첩장은 인사말 뒤, ‘예식 일정’ 바로 위에 갤러리를 표시해야 한다.
- **FR-002** — 청첩장 생성 시 `assets/` 및 하위 폴더의 모든 JPG, JPEG, PNG, WebP 사진을 파일명 사전순으로 배치한다. 사진 설명은 화면 읽기 프로그램에서 읽을 수 있어야 하며, 표지 사진은 기존 설정을 따라야 한다.
- **FR-003** — `assets/`에서 지원 이미지 파일을 찾지 못하면 갤러리 제목과 영역을 생략해야 한다.
- **FR-004** — 하객은 모바일과 데스크톱에서 가로 스크롤 없이 갤러리와 예식 일시·장소를 확인하고 길찾기 링크를 이용할 수 있어야 한다. 일부 사진을 불러오지 못해도 나머지 사진과 예식 정보, 길찾기를 이용할 수 있어야 한다.
- **FR-005** — `assets/`에서 발견한 사진을 읽을 수 없거나 지원 이미지 형식과 일치하지 않으면 생성 과정에서 문제 경로와 원인을 알려주고 이전에 성공한 결과를 보존해야 한다.
- **FR-006** — 게시용 갤러리는 `assets/`에서 검증한 사진으로 구성한다. 발견된 예시 사진은 게시용 검증에서 거부해야 한다.
- **FR-007** — 본문에는 대표 썸네일을 최대 5장 표시한다. 사진이 더 있으면 남은 장수를 표시하고, 사진을 선택하면 원래 비율로 크게 볼 수 있어야 한다. 상세 보기에서 등록한 모든 사진을 버튼이나 키보드로 순서대로 탐색할 수 있어야 한다.

### Key Entities *(include if feature involves data)*

- **갤러리 사진** — 작성자가 제공한 이미지와 표시 순서, 화면 읽기에 사용할 수 있는 사진 설명을 담는다.
- **사진 갤러리** — 청첩장 본문에서 예식 일정 바로 위에 표시되는 사진 모음이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — 공개용 사진 3장의 검증에서 모바일과 데스크톱 모두 파일명 사전순으로 3장 전부를 예식 일정 위에서 볼 수 있고, 설명 3개를 화면 읽기 프로그램에서 확인할 수 있다.
- **SC-002** — 화면 너비 320, 390, 1280픽셀에서 각각 갤러리와 예식 정보를 가로 스크롤 없이 볼 수 있고 길찾기를 이용할 수 있다. 사진 1장이 로드되지 않는 조건에서도 나머지 사진 2장과 예식 정보, 길찾기를 이용할 수 있다.
- **SC-003** — 폴더 없음, 빈 폴더, 사진 1장, 유효하지 않은 사진, 게시용 폴더에 예시 사진 포함의 5개 검증 사례가 모두 기대한 표시 또는 오류 결과와 일치한다.
- **SC-004** — 사진 5장과 10장을 등록했을 때 같은 화면 폭에서 본문 갤러리 높이가 같다. 10장일 때 `+5`가 표시되고, 상세 보기에서 마지막 사진까지 탐색할 수 있다.

## Assumptions

- ‘일정 전에’는 청첩장 본문의 ‘예식 일정’ 섹션 바로 위를 뜻한다.
- 공개할 사진은 작성자가 `assets/`에 넣는다. 파일명을 바꾸면 갤러리 순서도 바뀐다. 상세 보기의 이동은 하객이 제어한다.
- 게시 전 로컬 미리보기에서 사진과 순서를 확인하고, 게시 후에는 모바일과 데스크톱에서 게시 주소의 사진과 길찾기를 다시 확인한다.
