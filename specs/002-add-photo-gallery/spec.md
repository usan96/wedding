# Feature Specification: 예식 일정 위 사진 갤러리

**Feature Branch** — `main`

**Created** — 2026-11-20

**Status** — Draft

**Input** — 일정 전에 사진들을 보여줄 수 있는 영역이 필요해

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 예식 일정 위에서 사진 보기 (Priority: P1)

하객은 청첩장을 읽다가 인사말과 예식 일정 사이에서 웨딩 사진을 보고, 같은 페이지에서 예식 일시와 장소를 확인한다.

**우선순위 근거** — 사진 감상과 예식 정보 확인이 하객의 주된 이용 흐름이다.

**독립 검증** — 공개용 사진 3장이 등록된 청첩장을 휴대폰과 데스크톱에서 열어 사진 위치와 순서, 예식 정보와 길찾기 이용 여부를 확인한다.

1. **Given** 작성자가 사진 3장을 공개용으로 지정했을 때 **When** 하객이 인사말 아래로 스크롤하면 **Then** 예식 일정 바로 위에서 사진 3장을 지정된 순서대로 본다.
2. **Given** 하객이 모바일 또는 데스크톱으로 청첩장을 열었을 때 **When** 갤러리에서 예식 일정으로 이동하면 **Then** 가로 스크롤 없이 사진과 예식 일시·장소를 확인하고 길찾기 링크를 이용할 수 있다.
3. **Given** 설명이 등록된 갤러리 사진이 있을 때 **When** 하객이 화면 읽기 프로그램으로 갤러리를 읽으면 **Then** 해당 사진의 설명을 들을 수 있다.

---

### User Story 2 - 공개할 갤러리 사진 관리하기 (Priority: P2)

청첩장 작성자는 기존 청첩장 작성 과정에서 갤러리에 표시할 사진과 순서, 사진 설명을 정하고 결과를 미리 본다.

**우선순위 근거** — 사진이 확정된 후 작성자가 공개 범위와 표시 순서를 직접 관리할 수 있어야 한다.

**독립 검증** — 사진을 추가하고 순서를 바꿔 다시 생성한 뒤, 등록하지 않은 사진과 예시 사진의 공개 여부, 사진이 없는 입력, 누락된 사진 경로를 각각 확인한다.

1. **Given** 작성자가 사진과 설명을 등록하고 순서를 지정했을 때 **When** 청첩장을 생성하면 **Then** 지정한 사진과 설명이 순서대로 반영되고 표지 사진은 기존 설정을 따른다.
2. **Given** 기존 청첩장에 갤러리 입력이 없거나 작성자가 등록한 갤러리 사진을 모두 제거했을 때 **When** 청첩장을 생성하면 **Then** 갤러리 제목과 빈 영역이 생략되고 예식 일정이 표시된다.
3. **Given** 작성자가 존재하지 않는 사진을 등록했을 때 **When** 청첩장을 생성하면 **Then** 작성자는 문제 항목과 원인을 확인할 수 있고 이전에 성공한 결과는 보존된다.
4. **Given** 작성자가 제공한 사진 중 일부만 공개용으로 지정했을 때 **When** 게시용 결과를 생성하면 **Then** 지정한 사진만 갤러리에 포함된다. 예시 사진을 갤러리에 지정한 입력으로 게시용 결과를 생성하면 게시용 검증에서 해당 항목이 거부된다.

### Edge Cases

- 사진이 1장만 등록되어도 같은 위치에 갤러리가 표시된다.
- 하객이 청첩장을 열었을 때 사진 한 장을 불러오지 못해도 나머지 사진과 예식 일정, 길찾기는 이용할 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001** — 갤러리 사진이 1장 이상 등록되면 청첩장은 인사말 뒤, ‘예식 일정’ 바로 위에 갤러리를 표시해야 한다.
- **FR-002** — 작성자는 기존 청첩장 작성 과정에서 제공한 갤러리 사진과 표시 순서, 사진별 설명을 지정할 수 있어야 한다. 생성 결과는 지정 순서를 따르고, 등록된 설명은 화면 읽기 프로그램에서 읽을 수 있어야 하며, 표지 사진은 기존 설정을 따라야 한다.
- **FR-003** — 갤러리 입력이 없거나 사진 수가 0장이면 갤러리 제목과 영역을 생략해야 한다.
- **FR-004** — 하객은 모바일과 데스크톱에서 가로 스크롤 없이 갤러리와 예식 일시·장소를 확인하고 길찾기 링크를 이용할 수 있어야 한다. 일부 사진을 불러오지 못해도 나머지 사진과 예식 정보, 길찾기를 이용할 수 있어야 한다.
- **FR-005** — 갤러리용으로 등록한 사진이 존재하지 않으면 생성 과정에서 문제 항목과 원인을 알려주고 이전에 성공한 결과를 보존해야 한다.
- **FR-006** — 게시용 갤러리에는 작성자가 제공하고 공개용으로 지정한 사진만 포함해야 한다. 예시 사진이 등록된 입력은 게시용 검증에서 거부해야 한다.

### Key Entities *(include if feature involves data)*

- **갤러리 사진** — 작성자가 제공한 이미지와 표시 순서, 화면 읽기에 사용할 수 있는 사진 설명을 담는다.
- **사진 갤러리** — 청첩장 본문에서 예식 일정 바로 위에 표시되는 사진 모음이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001** — 공개용 사진 3장이 등록된 검증에서 모바일과 데스크톱 모두 지정한 순서대로 3장 전부를 예식 일정 위에서 볼 수 있고, 등록된 설명 3개를 화면 읽기 프로그램에서 확인할 수 있다.
- **SC-002** — 화면 너비 320, 390, 1280픽셀에서 각각 갤러리와 예식 정보를 가로 스크롤 없이 볼 수 있고 길찾기를 이용할 수 있다. 사진 1장이 로드되지 않는 조건에서도 나머지 사진 2장과 예식 정보, 길찾기를 이용할 수 있다.
- **SC-003** — 입력 생략, 빈 목록, 사진 1장, 존재하지 않는 사진, 게시용 입력에 예시 사진 사용의 5개 검증 사례가 모두 기대한 표시 또는 오류 결과와 일치한다.

## Assumptions

- ‘일정 전에’는 청첩장 본문의 ‘예식 일정’ 섹션 바로 위를 뜻한다.
- 작성자가 게시할 사진과 표시 순서를 정한다. 사진 확대, 자동 넘김, 별도 업로드 화면은 이번 범위 밖이다.
- 게시 전 로컬 미리보기에서 사진과 순서를 확인하고, 게시 후에는 모바일과 데스크톱에서 게시 주소의 사진과 길찾기를 다시 확인한다.
