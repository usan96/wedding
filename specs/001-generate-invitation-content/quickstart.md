# Quickstart — 청첩장 생성 검증

이 절차는 구현을 마친 뒤 저장소 루트에서 실행한다. Python 3.11 또는 이를 실행할 수 있는 `uv`, 모바일·데스크톱 브라우저, 게시를 검증할 때는 작성자가 확정한 예식 정보와 사진이 필요하다. 입력 예시는 [생성 명령 계약](contracts/generator.md), 각 필드와 규칙은 [데이터 모델](data-model.md)을 확인한다.

## 1. 초안과 정보 갱신 확인

```sh
uv run --no-cache --python 3.11 python scripts/generate_invitation.py
uv run --no-cache --python 3.11 python -m http.server 8000 --bind 127.0.0.1
```

1. `http://localhost:8000/`에서 제공된 예시 입력으로 생성한 초안 표시와 예시 사진을 확인한다.
2. `invitation.json`에서 이름과 날짜를 수정한다. 예를 들어 `2027-03-13`에서 `2027-04-18`로 옮긴다. 시각, 예식장, 주소와 링크를 바꾸고 첫 번째 명령을 한 번 다시 실행한다.
3. 새로고침해 제목·표지·인사말의 이름과 표지·일정의 날짜가 일치하고, 달력이 4월과 예식일 18일 일요일을 가리키는지 확인한다. 시각, 장소, 주소, 링크도 입력과 대조한다. 선택 항목을 지우면 해당 줄이 사라지고, 이름이나 장소의 앰퍼샌드와 인용부호는 원문대로 읽을 수 있어야 한다.

## 2. 입력 오류와 이전 결과 보존 확인

1. 유효한 입력으로 생성에 성공한 뒤 기존 파일의 해시를 기록한다.

   ```sh
   sha256sum index.html
   ```

2. 필수 이름 누락, `2027-02-29`, `24:00`, `/map`, 존재하지 않는 사진 경로를 각각 한 번씩 입력한다. 각 시도에서 생성 명령이 실패하고 표준 오류에 문제 필드와 이유가 표시되며 `index.html` 해시가 유지되는지 확인한다. 매번 해당 필드를 복구한 후 다음 사례를 확인한다.
3. 마지막에 유효한 값으로 다시 생성해 복구가 되는지 확인한다. 결과 파일이 없는 별도 검증용 체크아웃에서도 오류 입력으로 실행해 불완전한 결과가 남지 않는지 확인한다.

## 3. 게시용 파일과 프로젝트 경로 검증

```sh
preview_parent=$(mktemp -d)
uv run --no-cache --python 3.11 python scripts/generate_invitation.py --publish-dir "$preview_parent/wedding"
```

1. 예시 입력으로 실행하면 실패해야 하며, 지정한 위치에 게시용 번들이 생기지 않아야 한다.
2. 작성자가 제공한 확정 정보를 채우고 사진을 `assets/`에 둔다. 로컬 미리보기에서 이름과 일시, 장소, 사진, 길찾기 목적지를 대조한 뒤 `status`를 `confirmed`로 설정하고 위 게시용 명령을 다시 실행한다.
3. 다음 명령으로 게시용 파일과 `/wedding/` 아래 상대 경로를 확인한다.

   ```sh
   find "$preview_parent/wedding" -type f
   uv run --no-cache --python 3.11 python -m http.server 8001 --bind 127.0.0.1 --directory "$preview_parent"
   ```

4. `http://localhost:8001/wedding/`에서 `index.html`, CSS, 공유 스크립트와 지정한 사진 한 장만 제공하는지 확인한다. 이전 성공 번들 이후 현재 입력을 잘못된 값으로 바꿔 다른 새 경로에 게시용 생성을 시도하면 실패해야 한다. 확정 입력으로 되돌린다.
5. 모바일과 데스크톱에서 가로 스크롤 없이 예식 일시·주소를 읽을 수 있는지 확인한다. 모바일에서 길찾기 링크를 터치하고, 데스크톱에서 마우스와 키보드로 같은 목적지를 연다. 공유와 주소 복사도 확인한다.

## 4. 실제 게시 결과 확인

GitHub Pages 게시 소스가 GitHub Actions로 설정된 저장소에서 검토한 확정 입력과 자산이 담긴 커밋으로 기존 **Deploy invitation to GitHub Pages** 워크플로를 수동 실행한다. 완료 후 모바일과 데스크톱에서 배포 URL의 확정 정보, 리소스 로드와 길찾기·공유를 다시 확인한다.
