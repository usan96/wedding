# 모바일 청첩장 Constitution

## Core Principles

### I. 예식 일시와 장소

게시할 날짜와 시작 시각은 사용자가 확정한 예식 안내와 대조해야 한다. 요일이나 오전·오후를
표시하는 경우 확정된 날짜와 시각에 맞아야 한다. 예식장 명칭과 주소를 확인하고, 표시하는 경우
홀 이름과 층도 대조해야 한다. 길찾기 링크는 동일한 예식장을 가리켜야 한다.

### II. 신랑·신부와 가족 이름

신랑·신부와 청첩장에 소개하는 가족의 이름은 사용자가 확정한 표기와 글자 단위로 대조해야 한다.
각 이름이 올바른 사람과 관계에 연결되어 있는지도 확인해야 한다.

### III. 계좌번호와 연락처

계좌번호와 연락처는 사용자가 공개하기로 확정한 항목만 게시해야 한다. 계좌번호는 자릿수와
숫자 순서를 확인하고, 함께 표시하는 은행명과 예금주도 대조해야 한다. 연락처는 해당 인물과
전화번호의 연결을 확인해야 한다. 복사 또는 전화 걸기 기능이 있으면 그 값도 게시용으로
확정한 값과 일치해야 한다.

### IV. 변경 시 재검증

정보를 처음 게시하거나 변경할 때는 최신 확정 정보와 대조하고, 같은 정보가 표시되거나
사용되는 모든 위치에서 값이 일치하는지 확인해야 한다. 확인이 끝난 값만 게시해야 한다.
개발용 예시 정보는 예시임을 명시하고 공개 배포본에서 제외해야 한다.

### V. 모바일·데스크톱 호환

모바일과 데스크톱 브라우저에서 예식 일시와 장소를 가로 스크롤 없이 읽을 수 있어야 한다.
게시된 정보와 링크는 두 환경에서 모두 이용할 수 있어야 한다. 길찾기처럼 자주 사용하는
링크는 모바일에서 쉽게 터치할 수 있어야 하고 데스크톱에서 마우스와 키보드로 사용할 수 있어야 한다.

## 구현 제약

초기 사이트는 `index.html`을 진입점으로 하는 정적 사이트로 구성하고 GitHub Pages 프로젝트
경로 `/wedding/`에서 정상적으로 제공할 수 있어야 한다. 저장소 내 이미지, CSS, JavaScript는
상대 경로로 참조해야 한다. 저장소에는 정적 사이트를 GitHub Pages에 게시할 수 있는
GitHub Actions 워크플로가 있어야 한다. 예식 정보와 사진은 사용자가 제공한 자료를 사용해야 한다.

## 게시 및 검증 절차

- **게시 전** 모바일과 데스크톱 브라우저에서 로컬 미리보기를 열어 표시값을 확정 정보와
  대조하고 화면 배치, 길찾기 링크, 각 환경에서 제공되는 복사·전화 기능을 확인해야 한다.
- **게시 후** GitHub Actions 배포가 성공했는지 확인해야 한다. 모바일과 데스크톱 브라우저에서
  GitHub Pages 주소를 열어 확정 정보가 표시되고 링크와 사이트 리소스가 정상적으로 작동하는지
  확인해야 한다.

## Governance

헌장은 프로젝트의 명세, 구현 계획 및 변경 검토에 적용한다. 변경 검토 시 해당 원칙의 준수
여부를 확인해야 한다. 헌장을 개정할 때는 변경 내용과 이유를 정리해 사용자 승인을 받고,
버전과 최종 개정일을 갱신해야 한다.

기존 의무와 호환되지 않는 원칙의 삭제나 재정의는 주 버전을 올린다. 새 원칙을 추가하거나
기존 의무를 실질적으로 확대하면 부 버전을 올린다. 의미가 그대로인 문구 수정은 패치 버전을
올린다.
